# maiasa-radio
自分専用の、AIニュースを学ぶための場です。

平日の朝5分、AI・経済・世界のニュースを2人の掛け合いで聞く「毎朝5分ラジオ」を作っています。

## 公開前の音声チェック

台本を外部のAI音声で読み上げ、**誤読がないことを確かめてから公開する**ための仕組みです。
ブラウザの読み上げ機能は使いません。

## 流れ

```
台本（Claude が毎朝作成）
  ↓ ① 事前チェック  読み間違えやすい言葉を見つけ、読みを決める
  ↓ ② 音声合成      外部のAI音声（Google Cloud Text-to-Speech・Chirp 3 HD）で1行ずつ作る
  ↓ ③ 事後チェック  できた音声を文字に起こし、台本の読みと照らし合わせる
  ↓ ④ 判定          全行合格 → 1本の音声にまとめて公開
                     不合格の行 → 食い違った部分を読み（ひらがな）に直して作り直す（最大3回）
                     直らない → 公開を止める（前日の回のまま。レポートを人が確認）
```

### ① 事前チェック（`pipeline/prepare.py`）

| 見つけるもの | 例 | 扱い |
|---|---|---|
| 英字の語 | Claude、CBS | 読み辞書（`reading_dict.json`）でカタカナにして音声に渡す。辞書になければ**止める** |
| 読み分けが必要な言葉 | 今日、明日、市場、何、行った | 台本の行に `"yomi"` で読みが指定されていなければ**止める** |
| 数字＋助数詞 | 1分、6杯 | 同上 |
| 数字 | 200億、1,200 | 音声にはそのまま渡し、③で読みを確認 |
| 辞書にない漢字語 | — | **止める** |

「止める」と、毎朝の自動実行では Claude が文脈から読みを決めて台本に書き込み、もう一度チェックします。
読みを指定した例（`episodes/2026-11-05.json`）:

```json
{"speaker": "sora", "text": "それではまた明日。明日、金曜日は経済の回です。", "yomi": {"明日": "あした"}}
```

### ③ 事後チェック（`pipeline/check.py`）

台本と文字起こしの両方を、同じルールでカタカナの読みにそろえて比べます（形態素解析は fugashi + unidic-lite）。
合格の条件は次の3つすべてです。

1. **用語**：読み辞書に登録した言葉の読みが、聞き取り結果に含まれている（Claude→「クラウド」などを検出）
2. **数字**：2桁以上か、万・億・兆の付く数字の読みが、すべて含まれている（200億→2000億などを検出）。後ろに単位（ドル・円など）があれば、数字と単位の組み合わせで確かめる（110億ドル→110億円などを検出）
3. **全体**：読みの一致率が 93% 以上（読み飛ばし・言い間違い・音声の乱れを検出）

用語の条件を別にしているのは、長い行だと名前を1語読み間違えても一致率が 96% 程度にしか下がらず、全体の一致率だけでは見逃すためです。

## 使い方

```bash
pip install --use-pep517 -r requirements.txt
```

```bash
python -m unittest discover -s tests -t . -v
```

```bash
python -m pipeline.gate episodes/2026-11-05.json --prepare-only
```

```bash
python -m pipeline.gate episodes/2026-11-05.json --simulate tests/fixtures/simulated_2026-11-05.json
```

本番（音声を作る）には、Text-to-Speech API と Speech-to-Text API を有効にした Google Cloud の API キーが必要です。
キーは `X-Goog-Api-Key` ヘッダーで送ります。

- **Claude Code のクラウド環境**：キーは環境の「ネットワークシークレット」に保存します（`texttospeech.googleapis.com` と `speech.googleapis.com` の2つ）。プロキシが本物のキーに差し替えるので、コード・チャット・リポジトリにキーを書く必要はありません。
- **手元のパソコン**：環境変数で渡します。

```bash
export GOOGLE_API_KEY=...
```

```bash
python -m pipeline.backends --list-voices
```

```bash
python -m pipeline.gate episodes/2026-11-05.json
```

終了コード：`0` 公開OK（`build/<日付>/episode.wav` と `report.json`）、`2` 公開保留、`3` 事前チェックで停止。

## 設定（`config.json`）

| 項目 | 内容 |
|---|---|
| `voices` | 話し手ごとの声。解説役ハル＝Charon、聞き役ソラ＝Leda（2026年11月18日、サンプルを聞いて決定）。ほかの声は `--list-voices` で確認できる |
| `min_ratio` | 全体の一致率の合格ライン（0.93） |
| `max_attempts` | 1行あたりの作り直し回数の上限（3） |
| `stt` | 文字起こし。`google`（標準。Speech-to-Text）か `whisper`（無料。モデルを取得できる環境だけ） |

## 毎朝の自動化での置き場所

すべて Claude Code の定期実行（平日の朝）の中で行います。

1. ニュースを集めて台本（`episodes/<日付>.json`）を作り、①で止まった言葉の読みを決める
2. `python -m pipeline.gate` を実行する（音声合成・文字起こしは Google）
3. 終了コードが 0 なら、音声と台本をページ（claude.ai のアーティファクト。非公開）に公開する。2 か 3 なら公開せず、前日の回のままにして知らせる
4. ページで押された評価はページ内のデータに保存され、翌朝の Claude が読んで話題選びに反映する

細かい手順は `CLAUDE.md`（毎朝の定期実行が従う手順書）にあります。

| ファイル | 役割 |
|---|---|
| `web/radio.html` | 本番のページ（音声に字幕・スライド・口パクを合わせて再生、評価の保存） |
| `pipeline/site.py` | 台本と公開前チェックの結果から、ページ用のデータ（`site/data/`）と音声（`site/audio/`）を作る |
| `pipeline/prefs.py` | ページで押された評価から、話題の好みを計算する |
| `web/demo.html` | 最初の試作版（参考用） |

| 項目 | 月額 |
|---|---|

## 限界

- 文字起こしが漢字で返したとき（例：「明日」）は、どちらの読みで話したか分かりません。このため、行で指定した読みで話したものとみなします。ひらがなや別の漢字（例：「あす」「行なった」）で返れば、食い違いとして検出できます。読み分けが必要な言葉は①で先に読みを決め、音声にはひらがなで渡すことで、そもそも誤読しにくくしています。
- 文字起こし自体の聞き間違いで、正しい音声が不合格になることがあります（安全側に倒れる）。そのため、不合格の行は同じ音声を別の方式（`latest_short`）でも聞き直し、どちらかで合格すれば合格とします。3回直らなければ公開を止め、確認用の音声（`build/<日付>/review.wav`、不合格の行は `line-XX.wav`）を残して人の確認に回します。
- 2026年11月16日の本番テスト（Chirp 3 HD の Charon と Aoede、台本1,427字）では、音声の長さが約4分14秒でした。5分にするには、台本を1,700字ほどにします。
- 同じテストでは、正しく「110億ドル」と読んだ音声を、文字起こしが2つの方式とも「110億円」と聞き取りました（人が聞いて確認済み）。数字と単位の照合では、このような行は要確認として公開保留になり、人の確認に回ります。
- Chirp 3 HD の「カスタム発音」機能は、効かないという報告があるため使っていません。代わりに、音声に渡す文そのものを読み（カタカナ・ひらがな）に置き換えています。
- 声の名前（`config.json`）は仮の値です。実際に一覧を取って確認してください。
- 誤読を直したら `reading_dict.json` に追加し、同じ間違いを繰り返さないようにします。
